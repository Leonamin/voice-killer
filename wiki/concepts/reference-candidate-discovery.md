# 기준 오디오 후보 자동 탐색

상태: **1단계 구현됨(애드온)**. 단독 발화 후보만 구현했고, 화자 병합 UI·음성 아님 소리 분류·품질 평가는 하지 않았다. 구현 전 구상 수치는 미검증이다. 실측은 "구현 1단계" 절에 따로 적는다.

## 배경

- 현재 제거 기준(등록 음성)은 사용자가 원본에서 대상 화자 구간을 직접 찾아 구간 선택기로 지정하거나 별도 파일로 올린다. 화자 구분은 사람 귀로 한다.
- 엔진에는 화자 분리(diarization)나 화자 자동 구분이 없다. `engine.remove`는 등록 음성 1개만 받는다.
- 목표는 "구간을 직접 찾는 수고"를 줄이는 것이다. 화자 A를 자동 확정하는 것이 아니다.

## 원칙

- **기존 방식은 그대로 둔다.** 기준 오디오 직접 넣기와 구간 선택기를 유지한다. 후보 탐색은 그 앞에 붙는 선택 기능이다.
- **후보는 추천이지 확정이 아니다.** 사용자가 미리 듣고 고르거나 구간을 다듬는다. 자동으로 제거까지 진행하지 않는다.
- **깨끗한 구간만 후보로 올린다.** 정확한 화자 분류보다 "한 사람만 말하는 구간"을 고르는 것이 우선이다.
- 후보를 찾지 못하면 실패를 숨기지 않고 "후보 없음"으로 알리고 수동 방식으로 돌려보낸다.

## 우려 (사용자 제기)

1. 목소리가 깔끔하게 분리되지 않을 수 있다. 배경 잡음, 음악, 환호가 섞인 구간이 후보가 될 수 있다.
2. 동시 발화 구간이 후보로 잡힐 수 있다. 두 사람이 섞인 구간을 기준으로 쓰면 등록 음성이 오염되어 제거 대상이 흐려진다.

이 두 가지는 이 기능의 핵심 위험이며, 아래 설계는 이 둘을 줄이는 쪽에 맞춘다.

## 처리 흐름 (안)

```text
원본 → 16 kHz 모노 → VAD(음성 구간)
     → 화자 분리: 구간별 화자 임베딩 + 클러스터링
     → 동시 발화 탐지: 겹침 구간 표시
     → 후보 선별: 클러스터별로 깨끗한 구간 점수화
     → 클러스터당 상위 구간을 이어 붙여 후보 오디오 생성
     → 사용자가 미리 듣기·선택·다듬기 → 기존 remove에 기준 오디오로 전달
```

### 후보 선별 기준 (안)

- 겹침 제외: 동시 발화로 탐지된 구간과 그 앞뒤 여유 구간은 후보에서 뺀다.
- 최소 길이: 엔진이 요구하는 1초 이상 비무음(`check_enrollment`)을 하한으로 하되, 실제 권장 길이는 실측으로 정한다.
- 일관성: 클러스터 중심 임베딩과 가까운 구간을 우선한다. 멀면 다른 화자나 잡음일 수 있다.
- 잡음 억제: 음성 확률이 낮거나 음량 대비 잡음이 큰 구간은 점수를 낮춘다.
- 이어 붙이기: 클러스터마다 점수 상위 구간을 모아 하나의 후보로 만든다. 이어 붙인 경계에서 소리가 튀지 않는지는 확인이 필요하다.

### 표시 (안)

- 후보 목록에 "화자 1, 2, …"처럼 중립 이름과 총 길이, 구간 수를 보여 준다. A/B 같은 의미를 붙이지 않는다.
- 각 후보는 파형 플레이어로 미리 듣고, 원본 위에서 해당 구간 위치를 볼 수 있게 한다.
- 신뢰도가 낮으면(구간이 짧거나 겹침 비율이 높음) 경고 표시를 한다.
- 잡음·음악·환호 위주 클러스터는 화자 후보에서 숨기거나 "음성 아님 가능"으로 표시한다.

## 논의로 정한 설계 방향 (구상 단계 결정)

- **단독 발화 구간만 후보.** 프레임 단위 겹침 탐지로 동시 발화를 찾고, 겹침과 앞뒤 여유(0.3~0.5초 안)를 후보에서 뺀다. 놓친 겹침은 남으므로 "단독 발화로 추정"이라고 표시한다.
- **동시 발화는 후보군으로 만들지 않는다.** 두 사람이 섞인 소리는 기준 오디오로 쓸 수 없다. 타임라인에 회색 "겹침" 띠로만 표시해 후보가 없는 이유를 설명한다.
- **같은 화자를 여러 목소리로 쪼개지 않는다.** 클러스터링은 마이크 거리·감정·음량 변화로 한 사람을 쪼개기 쉽다. 다른 사람을 합치는 쪽이 기준 오염으로 더 치명적이므로 자동 병합은 보수적으로 하고, 쪼개짐은 사용자가 "같은 사람 합치기"로 고친다. 화자 수를 아는 경우를 위한 선택 입력과, 유사도가 높은 쌍의 "같은 사람일 수 있음" 표시를 둔다.
- **화자 그룹당 후보는 여러 개.** 이어 붙인 오디오 하나 대신 단일 연속 구간 상위 N개(3~5개 안)를 시간대가 떨어지게 뽑는다. 이어 붙인 "자동 조합" 후보는 마지막에 덧붙이는 정도로 둔다. 이어 붙임 경계 문제를 피하려는 것이다.
- **음성 아님 소리의 처리.** 환호·박수·웅웅거림처럼 형태가 일정하지 않은 소리는 제거해도 의미가 없으므로 화자 후보와 제거 대상 모두에서 제외한다. 현재는 후보를 오염시키지 않게 걸러내는 것까지만 목표로 한다(아직 구현·검증 안 함).
- **악기는 나중 후보(이번 범위 제외).** 사용자의 의도는 "기준 소리와 비슷한 소리끼리 묶어 제거"이며 사람 목소리처럼 악기도 묶일 수 있다는 가설이다. 미검증 사항: 화자 분리 모델은 사람 목소리 구분용이라 악기를 묶는 데 쓸 수 있는지 모르고, 현재 제거 엔진은 목소리 등록 기반이라 악기를 기준으로 줘서 지워지는지 확인된 바 없다. 악기를 종류별로 나누려면 분류가 아니라 음원 분리가 필요할 수 있고, 여러 악기가 섞이면 하나로 뭉칠 수 있다. 착수 전에 음악이 든 파일로 현재 모델이 악기 구간을 어떻게 다루는지부터 확인한다.
- **화자별 발화 시간·비율 표시는 필수가 아니다.** 웹 UI는 "제거할 기준 목소리"를 고르는 흐름이고 어느 쪽을 지울지는 사용자가 정하므로, 화자 선택용 별도 단서는 만들지 않는다. 총 길이와 구간 수 표시는 유지한다.
- **엣지 케이스.** 클러스터가 1개면 "한 명만 말하는 것 같음"으로 안내한다. 단독 발화가 1초 미만이면 "후보 없음"으로 알리고 수동 방식으로 돌려보낸다.
- **구현 순서 안.** 먼저 VAD와 겹침 탐지로 단독 발화 구간 후보를 길이순으로 보여 주는 단순 버전을 만들고, 쓸 만하면 화자 클러스터링과 병합 UI를 얹는다.

## 모델 후보 (웹 검색 기반, 모두 미검증)

검색으로만 확인한 내용이다. 다운로드·실행·라이선스 원문 확인은 하지 않았다.

| 후보 | 겹침 인식 | 알려진 제약 |
| --- | --- | --- |
| pyannote segmentation-3.0 | 파워셋 출력으로 프레임별 화자 0~3명·쌍 겹침을 구분한다. 겹침 탐지 파이프라인도 제공 | 10초 단위 모노 16 kHz 입력. 모델 카드 복사본은 MIT로 표기하나 원본 페이지 확인 필요. Hugging Face 토큰이 필요하다는 언급 있음 |
| NVIDIA Streaming Sortformer(Nemotron 3 Diarization 계열) | 화자 슬롯 방식으로 겹침에 강하다고 소개. 기본 4명 제한, 신형은 8명이라는 언급 | 라이선스 표기가 자료마다 다름(CC-BY-4.0, openmdw-1.1). ONNX CPU 실행 사례가 있으나 자체 보고 수치 |
| sherpa-onnx 조합 | pyannote segmentation-3.0 + 화자 임베딩(예: 3D-Speaker CAM++) + 클러스터링을 ONNX로 CPU 실행 | sherpa-onnx 자체의 RTF 수치는 못 찾음. 직접 측정 필요 |

- 위 모델들은 화자 분리용이다. 악기·박수 같은 소리 분류는 별도 모델(예: 일반 오디오 이벤트 분류)이 필요하며 후보는 아직 조사하지 않았다.
- 공통 후속 확인: 라이선스 원문, 가중치 접근 조건, Ryzen 7 8745HS에서의 10분 파일 RTF, 잡스 영상에서의 겹침 탐지 품질.

## 구현 1단계 (애드온, 기존 흐름은 바꾸지 않음)

- 구성: `src/voice_killer/candidates.py`(sherpa-onnx diarization + 겹침 제외), `POST /api/candidates`, 기준 목소리 화면 위쪽의 "기준 목소리 후보 찾기" 카드(`web/src/Candidates.tsx`). 후보를 고르면 기준 구간만 바뀌고 이후 흐름(작업 실행)은 그대로다. 안 눌러도 기존 방식으로 쓸 수 있다.
- 모델: pyannote segmentation-3.0(sherpa-onnx 변환본, MIT 표기) + wespeaker en voxceleb resnet34 임베딩. 설치는 선택 사항 `scripts/setup_diarize.sh`(모델은 `models/diarize`, Git 제외). 모델이 없으면 API가 503과 안내를 반환한다. 임베딩 모델의 라이선스는 확인하지 않았다.
- 방식: 화자 분리 결과에서 정확히 한 사람만 활성인 구간을 구하고, 겹침 앞뒤 0.3초를 제외한 뒤 2초 미만은 버린다. 화자당 길이순 상위 5개, 10초 초과는 가운데 10초만 쓴다. 겹침 탐지를 별도 모델로 하지 않고 화자 분리 결과의 구간 겹침을 쓴다.
- 실측(16코어 장비, 스레드 4, 1회): 잡스 2007 10분 파일에서 44초(RTF 약 0.07), 화자 2명·겹침 3곳. 60초 데모에서 3초, 화자 2명. 후보를 직접 들어 라벨링하지 않아 오염률·화자 정확도는 **미검증**이다.
- 사용자 녹음 시험(1회): 분리는 되었으나 목소리 4개로 나뉘었다. 목소리 1·2는 같은 사람, 3은 다른 사람(맞음), 4는 후보 1개뿐이었다. 즉 같은 사람이 쪼개지는 문제가 확인됐다(임계값 0.5).
- 대응(구현): 화자 수 선택(자동, 1~6명)을 넣고, 자동 임계값을 0.7로 올렸다. 0.7은 튜닝하지 못한 추정값이며 잡스 10분 파일에서는 0.7에서도 2명이었다. 혼자 말한 구간 합계가 5초 미만인 목소리는 "말한 양이 적은 목소리"로 접어 둔다. 2초 미만 단독 발화는 후보에서 버리므로 짧게만 말한 화자는 목록에 나오지 않는다.
- 미구현: 같은 사람 병합 UI, 음성 아님 소리 걸러내기(악기 묶기는 나중 후보), 타임라인의 겹침 표시, 자동 후보와 수동 기준의 `remove` 품질 비교.

## 미검증 가정

- 범용 화자 분리 모델이 환호·박수가 많은 발표(잡스 영상 같은)에서도 쓸 만하게 화자를 나눈다.
- 동시 발화 탐지가 후보 오염을 충분히 줄인다. 탐지를 놓친 겹침은 남는다.
- 자동으로 만든 후보가 사람이 고른 기준 오디오와 비슷한 제거 품질을 낸다.
- CPU 전용 장비(Ryzen 7 8745HS)에서 10분 길이 파일의 화자 분리가 허용 시간 안에 끝난다.
- 후보 모델의 라이선스·배포 조건(가중치 접근 제한 여부 포함)이 공개 배포 구성과 맞는다.

## 먼저 할 실험 (안)

1. 잡스 10분 파일에서 화자 분리와 동시 발화 탐지를 돌리고, 결과 구간을 사람이 듣고 라벨링한다.
2. 측정: 후보 안에 다른 화자·환호·잡음·겹침이 섞인 비율, 화자 수 오류, 처리 시간(RTF).
3. 같은 대상에 대해 자동 후보와 수동 기준 오디오로 각각 `remove`를 실행하고 기존 평가 스크립트(`evaluate_asr.py`, `evaluate_overlap.py`)로 비교한다.
4. 후보가 반복해서 오염되면 "화자 분리 없이 겹침 없는 단독 발화 구간만 길이순으로 추천" 같은 단순 방식으로 범위를 줄이는 것을 검토한다.

## 미정 사항

- 사용할 화자 분리·겹침 탐지 모델과 설치 방식(메인 환경 또는 `.venv-seedvc`처럼 분리 환경).
- 후보를 파일 전체에서 한 번에 구할지, 사용자가 지정한 범위에서만 구할지.
- 후보 길이 상한과 이어 붙이기 방식.
- 웹 UI 위치(파일 올리기 화면의 구간 선택기 옆 또는 별도 단계).
