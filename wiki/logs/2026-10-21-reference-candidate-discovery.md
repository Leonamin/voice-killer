# 기준 오디오 후보 자동 탐색 구상

- 대화에서 확인한 현재 상태: 입력은 16 kHz 모노로 변환해 처리하며, 화자 분리와 자동 화자 구분은 없다. 기준 오디오는 사용자가 직접 지정한다.
- 결정(구상 단계): 기존 직접 지정 방식은 유지하고, 후보를 자동으로 추천하는 선택 기능을 앞에 둔다. 사용자가 듣고 고른다.
- 사용자 우려 기록: 깔끔한 분리가 안 될 수 있고, 동시 발화 구간이 후보가 될 수 있다.
- 미검증: 화자 분리 품질, 겹침 탐지 효과, CPU 처리 시간, 모델 라이선스. 구현과 실측은 하지 않았다.

- 추가 논의 결정(구상 단계): 겹침 구간은 후보에서 제외하고 타임라인에만 표시한다. 같은 화자 쪼개짐은 자동 병합을 보수적으로 하고 사용자 병합으로 고친다. 화자 그룹당 후보는 단일 연속 구간 여러 개로 한다. 형태가 불규칙한 소리(환호·박수·잡음)는 제외하고 악기처럼 뚜렷한 소리는 별도 그룹으로 잡는다(제거 대상으로 쓸지는 미정). 화자 선택용 발화 비율 표시는 만들지 않는다.
- 웹 검색으로 겹침 인식 모델 후보를 정리했다: pyannote segmentation-3.0, NVIDIA Streaming Sortformer, sherpa-onnx 조합. 라이선스·CPU 속도는 모두 미검증이다.
- 구현 1단계(애드온): sherpa-onnx 기반 단독 발화 후보 찾기를 기준 목소리 화면에 추가했다. 10분 파일 44초(스레드 4). 후보 품질은 아직 듣고 검증하지 않았다.

- 결정: 악기 묶기는 이번 범위에서 제외하고 나중 후보로 둔다. 의도는 비슷한 소리끼리 묶어 제거하는 것이며, 악기가 묶이는지·제거되는지는 미검증이다. 코드에는 악기 처리가 없다.
- 사용자 녹음에서 같은 사람이 둘로 쪼개지는 것을 확인해 화자 수 선택과 소량 목소리 접기를 추가했다. 자동 임계값 0.7은 미튜닝이다.
